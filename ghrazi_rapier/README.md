# Ghrazi rapier — backport from OSRS to LostCity rev 254

A Theatre of Blood weapon (OSRS obj 22324), backported straight from
`cache.osrs239` with `3draster/3rd/rscache/tools/port_lostcity` and its
manifest `port_lostcity/ghrazi_rapier.ini`. Same session, same method as
`scythe_of_vitur/` — that README has the fuller writeup of the shared
reasoning (why the identikit correspondence table does not apply to wield
models, how the label was actually settled); this one only covers what
differs.

## No LostCity reference

Same as the scythe: this tree preserves 7 September 2004, fifteen years
before Theatre of Blood. `grep -ril ghrazi LostCity_Server/content` finds
nothing but this port's own files. The item reuses the existing native
`weapon_stab` category (`skill_combat/configs/melee/swords.obj`'s own
category) for its base stats; the passive is authored fresh.

## Mechanics

The live item's passive: **+25% to the stab attack roll only** when wielded —
accuracy, not max hit, and only on the stab component of the roll (three of
the weapon's four attack styles roll stab against `weapon_stab_table`; the
fourth rolls slash and is unaffected, which matches the live item only
boosting stab). Applied in `[proc,player_combat_stat]` immediately after
`%com_stabattack` is computed and before anything reads it, gated on the item
rather than `weapon_stab` (shared with every other stab sword, none of which
have this passive).

Also applied in the `.`-prefixed PvP copy of the same proc
(`[proc,.player_combat_stat]`), unlike the scythe's cleave: this passive has
no PvP restriction in the live game, and LostCity's PvP melee genuinely reads
`.%com_stabattack` off this same calculation (the `.` convention is "the
other active player" through the same procs, not a separate combat system the
way NPC melee and PvP melee are), so leaving the PvP copy unpatched would have
been a real gap, not a safe omission the way it is for the scythe.

## Animations

**Four animations, from three different places** — only one of the four is a
new export, which is why "port the animations" is not one operation here.

| role | seq | name | source |
| --- | --- | --- | --- |
| stance | 809 | `human_ds_ready` | native — already in rev 254 |
| stab | 8145 | `ghrazi_rapier_attack` | **ported** — the item's own |
| slash | 390 | `human_sword_slash` | native — already in rev 254 |
| defence | 4177 | `warguild_parry_defend` | **ported** — Warriors' Guild, post-2004 |

The two native ones exist in rev 254 under the same name *and* at the same id
as in osrs239 (`pack/seq.pack` has `809=human_ds_ready` and
`390=human_sword_slash`). They are 2004-era animations that survived into
OldSchool, so exporting them would mint a duplicate of an asset this tree
already ships — referencing them by name *is* the port. `warguild_parry_defend`
has no rev-254 counterpart under any name and genuinely had to be exported.

`weapon_stab`'s style table rolls stab on three of its four buttons and slash
on the fourth, so the stab animation is what plays most of the time.

### The wrong turn this corrects, and why it was wrong

An earlier version of this port concluded from a name scan that the cache held
**one** animation for this weapon, and that its idle therefore had to fall back
to rev 254's generic `human_ready`. The scan was accurate and the conclusion
was wrong:

```sh
find_named --rev osrs230 cache.osrs230 --name rapier --type seq
#  -> ghrazi_rapier_attack, and nothing else
```

Three of this weapon's four animations are simply not named after it. **A name
scan finds assets authored *for* an item; it cannot find the ones an item
merely *uses*.** And nothing in the cache links an obj to its animations — that
mapping lives on the game's server, not in any config — so for a weapon whose
animations are shared, the ids have to come from outside the cache entirely.
Absence of a named asset is not evidence the behaviour does not exist.

## Model — what was verified and what was not

Single uniform vertex label, 50 in the source cache — the same equipment-grip
label as the scythe, retagged the same way and for the same reason. See
`scythe_of_vitur/README.md`, which carries the full evidence: OSRS label 50
maps to rev 254's held-weapon joint **66**, in both `[export:label_map]` and
`[export:rig_map]`, and that pairing is what lets the ported stab animation
and rev 254's native stance/slash drive the same model.

Verified after export: all 51 vertices carry 66, and no transform in the
retargeted animset names a label twice.

It was **17** at one point in this session and briefly **66-in-the-model-only**;
both are half-right and both are recorded in the scythe's README with the
failure each produces.

Still not checked: no live client this session, so nothing was confirmed by
eye — position, orientation and how the swing reads in motion are unverified.
